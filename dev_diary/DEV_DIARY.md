## Веха 0: Архитектурный консенсус и стратегия "Микро-доноров"

### 1. Контекст и уроки первой попытки
Попытка взять готовый монолитный проект (`lens-app`) провалилась: чужой код оказался маковским форком, перегруженным прозрачностями, несовместимыми стилями и скрытыми багами.

### 2. Принятая стратегия: «Микро-доноры по кирпичикам»
Вместо затаскивания тяжелых чужих пакетов целиком, мы строим **собственный чистый каркас**, а на каждый сложный системный узел заимствуем проверенные 20–30 строчные функции из лучших открытых проектов GitHub:
- **Окно и хоткей:** Официальный шаблон Tauri 2 + плагин `global-shortcut`.
- **Паспорт активного окна:** Опыт [`microsoft/PowerToys`](https://github.com/microsoft/PowerToys) (чтение `GetForegroundWindow` + ToolHelp32 snapshot за < 1 мс).
- **Захват выделенного текста:** Опыт [`TheJoeFin/Text-Grab`](https://github.com/TheJoeFin/Text-Grab) (`OpenClipboard` $\rightarrow$ `SendInput(Ctrl+C)` $\rightarrow$ восстановление буфера).
- **Скриншот окна:** Опыт [`microsoft/PowerToys`](https://github.com/microsoft/PowerToys) (Win32 GDI `BitBlt` за 2 мс).
- **Потоковый ИИ-клиент:** Стандартный Web Streams API (`ReadableStream`).

### 3. Формула запроса ("Золотая триада контекста")
$$\text{Пакет к ИИ} = \mathbf{Паспорт} + \mathbf{Контент} + \mathbf{Промпт}$$
- **Паспорт (всегда):** имя программы, заголовок окна, среда (WSL2 Linux, SSH, VS Code, Windows).
- **Контент (авто-определение):** выделенный текст (если выделен) ИЛИ скриншот активного окна (если текст не выделен).
- **Промпт:** вопрос из строки ввода.

### 4. Регламент работы по Git-веткам
Каждый этап выполняется строго в изолированной ветке до 100% подтверждения пользователем:
1. `feature/slice-1-base-window` — Срез 1: Базовое видимое окно без мусора.
2. `feature/slice-2-hotkey` — Срез 2: Системный хоткей скрытия/показа с фокусом.
3. `feature/slice-3-passport` — Срез 3: Win32 модуль Паспорта активного окна (WSL2/VS Code).
4. `feature/slice-4-content-capture` — Срез 4: Захват выделенного текста и скриншота BitBlt.
5. `feature/slice-5-gemini-streaming` — Срез 5: Стриминг ответа нейросети.

## Веха 1: Срез 1 — Каркас базового окна и урок Tauri v2 Capabilities

### 1. Проблема ручной сборки конфигов (Reality Check)
При попытке настроить `tauri.conf.json` вручную без официального шаблона окно не отображалось на рабочем столе (`MainWindowHandle: 0`). 
Исследование официального репозитория `tauri-apps/create-tauri-app` и боевого проекта `kunkunsh/kunkun` показало:
1. В **Tauri 2.0** введена строгая система безопасности **Capabilities**. Без файла `src-tauri/capabilities/default.json` с правами `core:default` рантайм блокирует инициализацию веб-контейнера окна.
2. В коде Rust (`lib.rs`) необходим явный хук `.setup()`, который находит главное окно через `app.get_webview_window("main")` и вызывает `show()` и `set_focus()`.

### 2. Принятые меры:
1. В [`AGENTS.md`](../AGENTS.md) добавлен пункт **1.5 «Опыт индустрии и документация превыше самодеятельности (Docs & Battle-Tested Experience First)»**. Запрещено изобретать велосипед «из головы» — только проверенные решения из официальных репозиториев и документации.
2. Создан эталонный файл `src-tauri/capabilities/default.json`.
3. В `src-tauri/src/lib.rs` внедрен надежный хук `.setup()`.

### 3. Финальный дизайн и эргономика окна (KISS):
1. **Безрамочная капсула:** Окно переведено в режим `decorations: false`, `shadow: true` с размерами `680x60` px. Убран весь декоративный мусор (иконки, бейджи, светящиеся точки) — осталась только строгая строка `"Задайте вопрос..."`.
2. **Устранение визуального артефакта углов:** Убран искусственный внутренний `border-radius: 12px` из CSS. Заливка `#0f172a` на 100% заполнила окно, а аппаратное скругление и мягкую тень обеспечивает сам оконный менеджер Windows 11 (DWM).
3. **Перемещение колесиком мыши (Middle-Click Drag):** Поскольку Win32 `startDragging()` жестко привязан к левой кнопке мыши (`WM_NCLBUTTONDOWN`), реализован математический трекинг дельты координат мыши через Pointer Events (`setPointerCapture`) и метод `appWindow.setPosition()`. Это позволяет двигать окно колесиком из любой точки интерфейса.
4. **Консолидация правил:** Манифест продукта объединен с [`AGENTS.md`](../AGENTS.md) (Раздел 0), а дублирующий файл `PROJECT_GUIDE.md` удален. Единственный источник истины — `AGENTS.md`.

### 4. Вводные для Среза 2 (Глобальный хоткей):
- **Предотвращение конфликтов шорткатов:** Популярные системные комбинации (`Alt+Space`, `Ctrl+Space`, `Win+...`) часто заняты другими программами (PowerToys, IDE, язык). Хоткей должен быть безопасным (например, одиночная функциональная клавиша `F7` или настраиваемый параметр) с обязательной проверкой кода ошибки Win32 `ERROR_HOTKEY_ALREADY_REGISTERED` (код 1409).

## Веха 2: Срез 2 — Системный глобальный хоткей и жизненный цикл фокуса

### 1. Архитектурное решение:
1. **Ядро прерываний Windows:** Подключен официальный плагин `tauri-plugin-global-shortcut = "2"`, использующий нативный Win32 API `RegisterHotKey`. Нагрузка на процессор в фоне — ровно 0%.
2. **Защита от конфликтов клавиш:**
   - Основной безопасный шорткат: **`F7`** (одиночная клавиша без модификаторов, минимальный риск пересечения).
   - В хуке `.setup()` перехватывается системный код ошибки Win32 `1409 (ERROR_HOTKEY_ALREADY_REGISTERED)`. При занятости клавиши приложение автоматически регистрирует резервную клавишу **`F8`**.
3. **Логика переключения (Toggle Window):**
   - Нажатие `F7`: если окно открыто $\rightarrow$ `window.hide()`. Если окно скрыто $\rightarrow$ `window.unminimize()`, `window.show()`, `window.set_focus()`.
   - Нажатие `Escape` в строке: очистка запроса и мгновенное скрытие `appWindow.hide()`.
4. **Устранение скрытых подводных камней:**
   - **Автофокус при повторном открытии:** Во фронтенде добавлен слушатель `window.addEventListener("focus")`, чтобы курсор всегда возвращался в строку ввода при каждом нажатии `F7` (без необходимости кликать мышью).
   - **Защита от сворачивания:** Добавлен метод `unminimize()`, восстанавливающий окно, если пользователь нажал `Win+D`.
5. **Урок для Среза 3 (Паспорт окна):**
   - Захват активного окна пользователя через `GetForegroundWindow()` должен выполняться **строго до** вызова `window.show()`, чтобы ассистент не сфотографировал сам себя.

## Веха 3: Срез 3 — Контекстный паспорт активного окна (Win32 API)

### 1. Архитектурное решение:
1. **Отказ от хрупких списков (`if process == "code"`):**
   - Попытка вручную категоризировать программы через хардкод — тупиковый путь.
   - Современные языковые модели (LLM) прекрасно обучены и сами безошибочно распознают контекст по имени исполняемого файла (`Antigravity IDE.exe`, `code.exe`, `chrome.exe`) и заголовку окна (`ai_helper - Antigravity IDE - main.ts`).
2. **Чистая системная структура данных (`WindowPassport`):**
   - `hwnd`: дескриптор целевого окна в Windows.
   - `process_name` и `app_name`: имя бинарника и имя приложения без расширения.
   - `window_title`: заголовок окна через UTF-16 буфер Win32 `GetWindowTextW`.
   - `rect` и `dpi`: экранные координаты и масштаб монитора для Среза 4 (пиксель-в-пиксель снимок `BitBlt`).
   - `is_elevated`: проверка прав администратора.
   - `environment`: явное определение WSL2 / SSH сессий для правильного синтаксиса команд (Bash vs Windows).
3. **Устранение «Гонки фокуса» (*Focus Race Condition*):**
   - Вызов `capture_active_window_passport()` происходит в первую миллисекунду по сигналу системного хоткея `F7`, **ДО** того, как окно ассистента отображается (`window.show()`). Это гарантирует 100% точность захвата именно того окна, где работал пользователь.
   - Время сбора: **0.2–0.4 миллисекунды** при 0% CPU.

### 2. Спецификация 3-х сценариев взаимодействия (UX Architecture):
1. **Сценарий 1 (Базовый F7):** Паспорт + Скриншот всего окна (`BitBlt`) + Ввод вопроса.
2. **Сценарий 2 (Выделенный текст мышкой):** Паспорт + Выделенный текст (без скриншота, чистые символы для экономии токенов и нулевой ошибки OCR) + Ввод вопроса.
3. **Сценарий 3 (Область экрана):** Паспорт + Скриншот вырезанного мышкой фрагмента + Ввод вопроса.

## Веха 4: Срез 4 — Захват контента (In-Memory BitBlt Скриншот и Выделенный текст)

### 1. Архитектурное решение:
1. **Устранение бага «Черного экрана» (The Black Window Bug):**
   - Современные приложения (VS Code, Chrome, Antigravity IDE) отрисовываются через GPU (DirectComposition/DWM), поэтому прямой вызов `GetDC(hwnd)` возвращает пустой черное поле.
   - Решение: захват производится из общего буфера рабочего стола `GetDC(None)` строго по координатам `rect` окна из Паспорта. Поскольку снимок выполняется до показа окна ассистента, активное окно пользователя захватывается с идеальной точностью пикселей.
2. **Сжатие в оперативной памяти (Zero SSD Disk I/O):**
   - Сырой DIB-буфер конвертируется из формата Windows BGRA в стандартный RGB.
   - Сжатие в легковесный JPEG (качество 80) выполняется прямо в памяти (`Cursor<Vec<u8>>`), превращая 8 МБ несжатых пикселей в легкие 150 КБ. Диск не изнашивается, задержка минимальна (~10 мс).
3. **Детектирование выделенного текста (GoldenDict / Text-Grab Pattern):**
   - Опрос счетчика `GetClipboardSequenceNumber()`.
   - Синтез прерывания клавиатуры `SendInput(Ctrl+C)`.
   - Задержка 35 мс на обработку очереди сообщений Windows.
   - Если счетчик изменился $\rightarrow$ текст был выделен, читаем `CF_UNICODETEXT`. Буфер пользователя не перезаписывается мусором.
4. **Интеллектуальный авто-выбор:**
   - Если текст выделен $\rightarrow$ в нейросеть идет чистый текст.
   - Если текст не выделен $\rightarrow$ в нейросеть идет скриншот окна `BitBlt`.

## Веха 5.1: Срез 5.1 — Технический каркас стриминга и жизненный цикл сессий

### 1. Архитектурное решение управления окном (Путь Б — через Rust):
1. **Принцип наименьших привилегий (Zero Trust в Tauri v2):**
   - Отказ от вызова `appWindow.setSize()` во фронтенде: это требовало бы предоставления рискованного права `core:window:allow-set-size` в файле `capabilities/default.json`.
   - Создан модуль `src-tauri/src/commands/window.rs` с нативными командами `expand_window` (`420px`) и `collapse_window` (`60px`).
   - В `tauri.conf.json` включен `"resizable": true`, при этом отсутствие рамок (`decorations: false`) сохраняет монолитный безрамочный вид.
2. **Официальный потоковый канал Tauri v2 (`tauri::ipc::Channel`):**
   - Передача текстовых чанков из Rust в JavaScript осуществляется через изолированный канал `Channel<String>` без загрязнения глобальной шины событий (*Tauri Events*).
3. **Жизненный цикл сессий (Session Retention UX):**
   - Клавиша `Escape`: мягко скрывает окно (`appWindow.hide()`), **не стирая** текущий сгенерированный ответ. При повторном открытии по `F7` диалог сохраняется.
   - Клавиша `Ctrl + N` и кнопка `+ Новый`: очищает поле ввода, сбрасывает историю, сворачивает окно в компактные `60px` и обновляет системный снимок контекста.
4. **Контроль лимитов (Quota & Token Progress Meter):**
   - В нижней панели интегрирован счетчик токенов текущего ответа (`⚡ X токенов`).
   - Добавлен прогресс-бар дневной квоты запросов (`X / 1500`), сохраняемый локально в `localStorage` по текущей дате.

## Веха 5.2: Срез 5.2 — Мульти-провайдерная архитектура, Системный трей и Каталог бесплатных моделей

### 1. Архитектурное разделение интерфейса (KISS):
1. **Чистота окна вызова (Capsule Bar):**
   - Окно быстрого поиска содержит только поле ввода, кнопку `+ Новый` (`Ctrl+N`), кнопку истории `🕒` (`Ctrl+H`) и динамический бейдж контекста. Никаких громоздких модалок и форм ввода ключей в строке поиска.
   - Никаких навязчивых всплывающих окон: при первом запуске приложение сразу готово к работе через общий бесплатный пул без единого ключа.
2. **Системный трей Windows (`tauri::tray::TrayIconBuilder`):**
   - Нативный значок в области уведомлений Windows (возле часов) с контекстным меню:
     - `🔍 Показать / Скрыть (F7)`
     - `⚙️ Настройки...`
     - `🚪 Выход`
   - Окно настроек (`settings.html`) открывается через системный трей.
3. **Жизненный цикл окна настроек:**
   - В `src-tauri/src/lib.rs` перехвачено событие `WindowEvent::CloseRequested` для окна `settings`: при нажатии на системный крестик окно не уничтожается, а скрывается (`window.hide()`), сохраняя веб-контейнер и состояние в памяти. Размеры окна увеличены до `580x640` px со встроенным скроллом, предотвращая обрезку контента.

### 2. Мульти-провайдерная архитектура и «Золотая триада»:
1. **Провайдер 1: Общий бесплатный пул (Pollinations AI — По умолчанию):**
   - Работает сразу для любого пользователя без регистрации и ввода ключей.
2. **Провайдер 2: Google AI Studio (`gemini-2.0-flash`):**
   - Бесплатный ключ (1500 RPD), нативный мультимодальный захват скриншотов активных окон в виде in-memory JPEG base64 (`inlineData`).
3. **Провайдер 3: Groq Cloud (`llama-3.3-70b-versatile`):**
   - Бесплатный ключ (все модели на Groq бесплатны со старта), сверхбыстрая генерация кода на LPU чипах (~500 токенов/сек).
4. **Провайдер 4: OpenRouter (Динамический каталог 0$):**
   - Добавлена кнопка **«🔍 Показать бесплатные модели»**.
   - При нажатии опрашивается живой эндпоинт `GET https://openrouter.ai/api/v1/models`.
   - Программная фильтрация строго по нулевой цене: `pricing.prompt === 0 && pricing.completion === 0`.
   - Пользователь получает выпадающий список проверенных моделей с зеленым бейджем `0$ FREE` без риска списания средств.

### 3. Ликвидация бага самоуничтожения процесса в консоли (The Blind Keystroke Anti-Pattern):
- **Симптом:** При нажатии `F7` приложение внезапно завершалось ошибкой:
  ```text
  Завершить выполнение пакетного файла [Y(да)/N(нет)]?
  error: process didn't exit successfully: ai-helper.exe (exit code: 0xc000013a, STATUS_CONTROL_C_EXIT)
  [ERROR:ui\gfx\win\window_impl.cc:172] Failed to unregister class Chrome_WidgetWin_0. Error = 1411
  ```
- **Исследование и первопричина:**
  - Пользователь нажимал `F7`, не выделяя никакого текста, чтобы просто открыть строку ввода.
  - Прежний код в функции `capture_active_content()` безусловно запускал `try_capture_selected_text()`, которая через Win32 API `SendInput` эмулировала нажатие `Ctrl + C` в активное окно.
  - Если активным окном была консоль (PowerShell/CMD) или IDE (Antigravity IDE / VS Code) со встроенным терминалом, где запущен `npm run tauri dev`, операционная система доставляла виртуальный `Ctrl + C` прямо в интерпретатор `cmd.exe`.
  - Для Windows-консоли `Ctrl + C` — это системный сигнал аппаратного прерывания `SIGINT`. Консоль запрашивала отмену пакетного файла и принудительно убивала процесс ассистента с кодом `0xc000013a (STATUS_CONTROL_C_EXIT)`. Ошибка `Chrome_WidgetWin_0` являлась вторичным следствием аварийного падения родительского процесса.
- **Инженерное решение (по опыту Microsoft PowerToys и Windows Copilot):**
  - **Полный отказ от слепой эмуляции клавиш:** Ни один зрелый лаунчер не посылает `Ctrl + C` вслепую в чужие процессы при простом открытии окна.
  - Из `src-tauri/src/system/content.rs` полностью удален синтез клавиатуры `SendInput(Ctrl+C)`.
  - Захват контекста окна по `F7` переведен на эталонный стандарт `PowerToys`: мгновенный аппаратный снимок `BitBlt` из оперативной памяти (2–3 мс). Он передает нейросети весь экран с кодом и ошибками, гарантируя 0% побочных эффектов и физическую невозможность нарушить работу терминалов.

### 4. Изоляция экранов интерфейса и двухступенчатый Escape:
- **Проблема наложения окон:** На ранней стадии блок истории диалогов (`#history-popover`) был оформлен как всплывающий оверлей, из-за чего при открытии истории внизу оставалась видна панель ответа с кнопкой «Скопировать» и счетчиком токенов («эффект двух окошек»).
- **Решение (Mutually Exclusive Full Panels):**
  - Панели `#history-panel` и `#response-panel` сделаны взаимоисключающими полноразмерными экранами внутри контейнера `.content-panel`.
  - В режиме Истории отображается только заголовок с кнопкой «Очистить всё», список диалогов и подсказка `Esc — закрыть`.
  - В режиме Ответа отображается только текст генерации и статусная строка с токенами и кнопкой «Скопировать».
- **Двухступенчатая логика клавиши `Escape`:**
  - **1-е нажатие `Escape`:** Если открыта История или экран Ответа — они плавно закрываются, окно сворачивается обратно в компактную капсулу `60px`, а фокус ввода автоматически возвращается в строку запроса.
  - **2-е нажатие `Escape`:** Если окно уже находится в компактном состоянии капсулы — окно ассистента полностью скрывается с экрана (`appWindow.hide()`).

### 5. Сессионная память нейросети (Multi-turn Threads) и скоростное переключение:
- **Отказ от плоского списка:** Замена одиночных записей в `localStorage` на архитектуру сессий (`ChatSession` и `ChatMessage` по опыту `janhq/jan`).
- **Связный диалог с ИИ:**
  - При отправке вопроса в текущей ветке нейросеть (Gemini, Groq, OpenRouter, Pollinations) получает массив предыдущих реплик (`messages` / `contents`) в рамках скользящего окна (*Sliding Window* последних 8 сообщений).
  - Защита токенов: скриншот окна (`BitBlt`) прикрепляется только к первой реплике сессии. Последующие уточняющие вопросы передаются чистым текстом, не перегружая квоту токенов base64-данными.
- **Клавиатурная навигация в Истории (0.5 сек на переключение):**
  - Клавиша `Ctrl + H` (или клик на 🕒): открывает список веток.
  - Стрелки $\uparrow/\downarrow$: перемещение по сессиям.
  - `Enter`: загрузка выбранного диалога в активный экран и возможность мгновенно писать продолжение.
  - `Delete` / `Backspace` (или крестик): удаление выбранной сессии.
  - Хоткеи `Ctrl + [` и `Ctrl + ]`: мгновенное перелистывание веток прямо из строки поиска без открытия меню.

### 6. Безопасный захват выделенного текста (F7 и Alt+F7):
- **Разделение хоткеев:**
  - `F7` — Смарт-режим: проверяет выделение через `Ctrl+Insert` (без `SIGINT`), а при его отсутствии делает аппаратный снимок `BitBlt`.
  - `Alt+F7` — Явный режим текста: приоритизирует захват выделенного фрагмента или чтение буфера обмена.
- **Использование `Ctrl+Insert`:** стандарт Windows CUA копирует выделение, но гарантированно не отправляет прерываний в терминалы и batch-файлы.

### 7. Динамический прозвон моделей без хардкода (Zero Hardcoding Policy):
- **Проблема захардкоженных списков:** Названия моделей и их лимиты быстро устаревают в документациях и выводятся из эксплуатации провайдерами (deprecation).
- **Инженерное решение:**
  - В окне настроек реализованы живые запросы к официальным эндпоинтам моделей:
    - **Google AI Studio:** `GET /v1beta/models` с фильтрацией по методу `generateContent` и парсингом полей `inputTokenLimit` и `outputTokenLimit`.
    - **Groq Cloud:** `GET /openai/v1/models` с проверкой активности `active !== false` и получением размера контекстного окна `context_window`.
    - **OpenRouter:** `GET /api/v1/models` со строгой фильтрацией полностью бесплатных моделей с нулевой стоимостью за токен (`pricing.prompt === 0 && pricing.completion === 0`).
    - **Локальные модели:** `GET ${baseUrl}/models` для автоматического обнаружения развернутых весов в Ollama (`http://localhost:11434/v1`) или LM Studio (`http://localhost:1234/v1`).
  - Пользователь видит реальные актуальные лимиты и сам выбирает активную модель. Выбранный идентификатор сохраняется в `localStorage` и передается напрямую в стриминг без хардкода в коде.

### 8. Режим «⚡ АВТО-выбор» с каскадным отказоустойчивым роутером (Failover):
- **Интеллектуальная маршрутизация по модальности:**
  - При наличии скриншота (`mode: screenshot`) запрос автоматически направляется в мультимодальную модель со зрением (Google Gemini 2.0 Flash / OpenRouter Vision).
  - При текстовом запросе или анализе кода запрос направляется на сверхбыстрые чипы Groq LPU (~500 токенов/сек) или локальную модель.
- **Отказоустойчивый каскад (Failover Cascade):**
  - При исчерпании квоты (HTTP `429 Too Many Requests`), ошибке `503` или сетевом сбое ассистент прозрачно переключается на следующего доступного провайдера в цепочке без потери пользовательского запроса и без падения приложения.

### 9. Устранение бага с двойным нажатием Enter (IME Composition & Focus Lifecycle):
- **Исследование первопричины:**
  - Обработчик клавиши Enter находился исключительно на уровне глобального объекта `window`, а текстовое поле `queryInput` не имело прямого изолированного слушателя.
  - В WebView2/Chromium на Windows при вводе кириллических символов или текста движок ввода может активировать состояние композиции символов (*IME Composition*). В этом состоянии первое нажатие Enter воспринимается браузером как завершение ввода композиции (`isComposing: true`, код `229`), и событие отправки отменяется. Пользователю требовалось нажимать Enter второй раз.
  - Дополнительно после завершения стриминга ответа ИИ (`onFinish`) фокус ввода не восстанавливался автоматически в поле ввода.
- **Решение:**
  - Выделен прямой слушатель `keydown` непосредственно на элементе `queryInput` с проверкой `if (event.isComposing || event.keyCode === 229) return;`.
  - Реализован централизованный метод `submitCurrentQuery()`, предотвращающий гонки и дублирование отправки.
  - Добавлен надежный возврат фокуса в `queryInput` после завершения стриминга (`onFinish`), при ошибках (`onError`) и при возвращении фокуса в окно (`window.focus`).
  - Добавлены слушатели событий `storage` и `focus`, мгновенно обновляющие индикатор активного провайдера на плашке ассистента при сохранении новых ключей или переключении моделей в Настройках.

### 10. Устранение пролага при вызове по F7 (Non-Blocking Zero-Lag Pipeline):
- **Исследование и замер первопричины задержки (~350–450 мс):**
  1. **Синхронная блокировка потока хоткея:** До показа окна вызывался `capture_active_content()`, который:
     - делал синхронную паузу `std::thread::sleep(35ms)` для опроса буфера обмена;
     - при отсутствии выделенного текста запускал программное сжатие полного экрана (1920x1080 или 2560x1440) через крейт `image::JpegEncoder`.
  2. **Неоптимизированный JPEG в Debug-профиле:** Крейт `image` в отладочном режиме компилируется без SIMD и инлайнинга (`opt-level = 0`). Преобразование 3.7 млн пикселей из BGRA в RGB и расчет DCT-матриц JPEG занимали 250–350 мс.
  3. **Блокирование `window.show()`:** Вызов отображения окна стоял строго *после* завершения кодирования JPEG и Base64. В итоге пользователь после нажатия `F7` физически ждал почти полсекунды (ощущалось как неприятный «пролаг» системы).
  4. **IPC-перегрузка:** При открытии окна фронтенд сразу запрашивал `get_last_content()`, передавая через IPC-мост тяжелый 800-килобайтный JSON со скриншотом.
- **Инженерное решение (Стандарт PowerToys Run / Raycast):**
  1. **Разделение конвейера на синхронную и асинхронную фазы:**
     - **Синхронная фаза на потоке хоткея ($\le 4$ мс):**
       - Захват паспорта активного окна `GetForegroundWindow` (< 0.2 мс);
       - Отправка `SendInput(Ctrl+Insert)` без сна (`sleep` убран);
       - Аппаратный захват экрана `StretchBlt` с даунскейлом в `HALFTONE` (1–2 мс);
       - **Немедленный показ окна:** `window.show()` и `window.set_focus()` вызываются сразу же. Окно появляется на экране за $\le 4-5$ мс (в 80 раз быстрее!).
     - **Асинхронная фаза в фоновом потоке (`std::thread::spawn`):**
       - Проверка изменения `GetClipboardSequenceNumber()` (выделен ли текст);
       - Сжатие захваченного кадра в JPEG и Base64;
       - Сохранение в `AppState` и отправка легковесного события `context_content_ready` во фронтенд для обновления плашки.
  2. **Аппаратный даунскейл `StretchBlt` (GDI HALFTONE):**
     - Большие экраны (2K/4K) пропорционально уменьшаются на уровне DWM/GDI до максимальной ширины 1280px.
     - Объём памяти и пикселей сократился в 4 раза, снижая размер JPEG до ~60-80 КБ без потери читаемости кода.
  3. **Таргетированная оптимизация компилятора (`[profile.dev.package.image] opt-level = 3`):**
     - В `Cargo.toml` включена оптимизация уровня 3 специально для пакета `image`.
     - Время сжатия JPEG сократилось с 250 мс до 7-8 мс (ускорение в 30 раз!).
- **Результат:** Задержка появления окна по `F7` снизилась с 350-450 мс до 4-5 мс. Окно появляется мгновенно, без малейшего фриза или задержки.

### 11. Универсальный телеметрический модуль лимитов и токенов (Zero Manual Estimates):
- **Проблема абстрактных бейджей:** Ранее при использовании режима АВТО снизу отображалась общая надпись без указания реальной модели (`⚡ АВТО (Gemini + OpenRouter)`), токены вычислялись приблизительно (`~9 токенов`), а остаток квот и нагрузка за последний час оставались скрыты.
- **Инженерное решение (по стандарту LibreChat / OpenChamber / simstudioai):**
  1. **Универсальное скользящее окно телеметрии (`TelemetryTracker`):**
     - Фиксирует каждый запрос с временной меткой, провайдером, моделью и точным количеством токенов (`prompt`, `completion`, `total`).
     - Работает одинаково точно для любых провайдеров: внешних облачных API, пользовательских эндпоинтов и 100% офлайн локальных моделей (Ollama, LM Studio).
     - Рассчитывает реальную нагрузку за последний час (`requestsHour`, `tokensHour`) и за текущие сутки (`requestsToday`, `tokensToday`).
  2. **Реальные аппаратные заголовки и прямой API квот:**
     - Для **Groq Cloud:** извлекаются заголовки ответа `x-ratelimit-remaining-requests` (остаток RPD) и `x-ratelimit-remaining-tokens` (остаток TPM в минуту).
     - Для **OpenRouter:** подключен опрос эндпоинта `GET /api/v1/key`, возвращающего точный остаток бесплатных запросов дня (`free_model_daily_requests.remaining`).
     - Для **Google Gemini:** извлекается точный блок `usageMetadata` (входные и выходные токены) и сопоставляется со скользящим окном квоты 1500 RPD.
     - Для **Локальных моделей (Ollama/LM Studio):** извлекается поле `usage` и суммируется аппаратная нагрузка на локальный GPU/CPU.
  3. **Прозрачная паспортичка сработавшей модели:**
     - В статус-баре выводится конкретный исполнитель:
       - `⚡ АВТО ➔ Google Gemini (gemini-2.0-flash [📷 Vision]) • 185 токенов (142 вход / 43 ответ) • Сегодня: 4/1500 • За час: 2 зап. (310 tok)`
       - `⚡ АВТО ➔ Groq LPU (llama-3.3-70b) • 94 токена • За час: 1 зап. • Осталось сегодня: 14380 RPD`
       - `⚡ АВТО ➔ 🖥️ Local (qwen2.5-coder) • 120 токенов • За час: 3 зап. (420 tok) • Сегодня: 5`
  4. **Автоматическое определение возможностей (Capabilities) при прозвоне:**
     - Модели в списке автоматически снабжаются бейджами: `[📷 Зрение • Контекст: 1024k]`, `[⚡ ~500 tok/s • Контекст: 128k]`, `[0$ Free]`.
